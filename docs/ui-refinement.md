# 桌面界面调整

沿用 WPF / .NET 10 与现有浅色、青色资源，不增加界面框架。按 Refactoring UI 先处理内容层级、分组和可操作性，再统一控件样式。

## 调整前检查

| 位置 | 严重程度 | 规则 | 现状 | 调整 |
| --- | --- | --- | --- | --- |
| HTTP 步骤与底部操作 | P0 | §2.1 / §8.4 | 截图中新增入口不明确，删除和排序缺少按钮，保存操作在滚动区底部 | 明确编辑开关与步骤工具栏；固定操作栏；提供空状态 |
| HTTP 表单 | P1 | §3.3 / §3.6 | 名称和函数各占整行，过多纵向留白挤压步骤 | 并列字段，区分动作信息、步骤、可选请求正文 |
| 主标签 | P1 | §2.1 / §2.8 | 连接、项目资源和脚本操作权重相同，缺少清晰分组 | 连接与发送参数归组；编辑器作为工作主体；运行脚本为主操作 |
| 列表、表格、下拉框 | P2 | §8.1 / §8.5 | 原生灰底、黑色网格线与现有主题割裂 | 统一背景、细分隔线、行高、选中及键盘焦点状态 |
| 设置窗口 | P1 | §3.3 / §3.6 | 设备字段纵向堆叠，保存按钮随内容滚动 | 按设备分组，限制字段宽度，固定保存栏 |

HTTP 项来自用户截图，其余同时结合源代码检查；最终以实际 WPF 渲染验证。

## 实现约束

- 主层级：脚本编辑及运行、HTTP 请求步骤；次层级：画面预览和项目资源；辅助层级：说明、路径、状态。
- 颜色复用 `PageBrush`、`PanelBrush`、`TextBrush`、`MutedBrush`、`LineBrush`、`AccentBrush`、`SoftBrush`。
- 间距 4 / 8 / 12 / 16 / 24 / 32；字号 12 / 14 / 16 / 20；普通和半粗两种字重；圆角 8。
- 三个主标签保持不变；编辑动作开关默认关闭；语法说明可展开；手动控制栏仍由设置决定是否显示。
- 表格展示顺序就是执行顺序，禁止按列排序；可选请求正文不挤占主要步骤区域。
- 桌面窗口按 1280 × 900 和最小支持的 1000 × 720 检查。此原生桌面程序不采用网页的 375 像素移动端检查。
- 测试只使用隔离项目与模拟画面，不发送机器人、ESP32 或主机操作。

## 渲染复查

实际渲染了主标签、HTTP、图像标签、语法说明、设置、声音和推送窗口。修正了自定义下拉框未显示显示名称、截图背景透明以及最小窗口下可选 HTTP 正文无法滚动访问的问题。HTTP 底部操作栏在 1000 × 720 仍可见；主标签使用滚动承载较长的编辑和采集内容。截图保存在本地 `work/ui-checks/`，使用隔离测试数据，不随源码提交。
